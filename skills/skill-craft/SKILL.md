# skill-craft：做技能的实证打法

一套从真实技能项目（工具型与文风型各一）完整走通提炼的方法论。核心信念：**技能是给模型的行为说明书——触发词决定用不用，理由决定听不听，示例决定像不像，验证决定靠不靠谱。**

## 先定标：按任务读对应内容

| 你正在做的事 | 读什么 |
|---|---|
| 写新技能 / 改 SKILL.md / 排查触发问题 | 本文主体（下面五节） |
| 技能要**发版**（tag / Release / 双平台） | 加读 `references/release.md` |
| 技能**需要 API key / 凭据**（脚本要读，或用户装完要配） | 加读 `references/credentials.md` |
| 写安装器 / 遇到编码、平台、网络坑 | `references/pitfalls.md` |

读完定标再动手。五节核心如下，任何技能类型都适用。

## 一、触发是第一生死线

- frontmatter `description` 是唯一常驻上下文的触发信号，必须**主动、带钩子**：做什么 + 何时触发 + 用户会说的原话变体（口语、方言、错别字："搜一下/查查/瞅瞅/latest"）。模型天然**漏触发**而非误触发，宁过勿缺。
- **工具竞争环境要明写优先级**：环境里存在内置工具（WebSearch/WebFetch）或同类竞品技能时，description 必须直接声明"优先用本技能，因为……（省 token/带编号引用/更可控）"。实证：没有这句时内置搜索抢走触发，加上后 10/10。
- 覆盖"用户没明说"的场景："即使没提到 X 也要加载"。
- **验证触发必须开全新会话测**（技能发现是会话启动时固定的）；标准动作是 10 问口语化/错别字触发测试，门槛 ≥9/10。

## 二、规则写法：理由 + 自检 + 示例，不写命令清单

- 每条规则带 **why**，尤其反直觉的（例："术语轮换是机器腔，行内人不换词"）——模型理解了原因，才会在规则没覆盖的边界情况做对。
- 每条规则给**可操作的自检**："把连接词删掉，逻辑变模糊就留，只是语气变平就删"；"整段能原样搬进任何领域就说明太空，重写"。
- **示例胜过规则**：SKILL.md 里放一段真实输出样例，比十条格式规定都管用；每条规则配前/后对照。
- 末尾放一条**裁决句**处理规则冲突："行内人会怎么做？冲突时以这句话为准。"

## 三、分层结构

- **硬约束层**（不可被任何配置推翻）> **原则层** > **习惯层** > **参考层**。
- **渐进披露**：metadata 精简；SKILL.md 主体 <500 行；细节按情境放 `references/` 并在正文写明何时读（按文体/学科/任务分文件都是好范式）。
- **文风型技能用"生成时约束"定位**：动笔前加载、产出即终稿，明确不做"先写后润"；并诚实声明非目标。
- **工具型技能用"阶梯"控制成本**：先低成本的（如 search，摘要层够 90% 场景），真正需要才高成本的（如 fetch 整页）——教模型"少做"和教它"做"一样重要。
- 双语技能做成**镜像孪生**（同骨架、各自本地化示例），不是机翻。

## 四、工程配套（工具型）

- 包结构：`SKILL.md + scripts/（零依赖单文件）+ references/ + runtime.conf`，自包含、无仓库外依赖。
- **错误信息写给 Agent 读**：无 key 报错 = 三步指引（取 key → 放哪 → 重试），Agent 读到就能引导用户，不需要人守着。详细设计见 `references/credentials.md`。
- **版本闭环**：安装器落位时打版本戳进 runtime.conf（`git describe --tags`，无 git 退 `dev`），自检命令首行回显版本；更新 = 幂等重跑安装器；README 必须有 Update 章节。
- 输出带冻结契约号（如 `contract: v1`），破坏性变更升版本——下游 Agent 可放心解析。

## 五、验证纪律（最贵的一节，全是翻车换的）

- **写进 README/发布说明的命令必须本机实证**，或明确标注"未验证"。警惕平台错配：工具的生态假设（GitHub）与仓库实际托管（GitCode）不同源时，`owner/repo` 类简写命令默认不可用。
- **安装器/脚本必须用目标解释器真跑**，且 happy path 和回退路径都要测。典型坑见 `references/pitfalls.md`（PS 5.1 无 BOM 按 GBK 解析报语法错；`$ErrorActionPreference='Stop'` 下原生命令 stderr 重定向抛终止性错误）。此类不变量写成单测守护（.ps1 含非 ASCII 必须带 BOM、.sh 绝不带 BOM）。
- **E2E 测模型行为决策而非仅功能**：低预算截断时模型会不会正确权衡？报错时会不会引导用户？引用要对照缓存溯源防幻觉 URL；关键事实用第二个工具交叉核对。
- 子代理 = 全新会话等价物，可测触发；注意供应商并发上限与用量上限，大批量分批 + 要求简答。

## 元教训

技能的每句话都在争夺模型的注意力与执行意愿。发布是一条流水线而不是一个动作（见 `references/release.md`）——从 CHANGELOG 到版本戳验证，任何一环"写了没验"都会在用户面前翻车。
